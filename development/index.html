Development#

pypillometry is developed and maintained by the Cognitive Neuroscience Research Group at UiT The Arctic University of Norway. Everyone is welcome to contribute, by reporting bugs, suggesting features or sending pull requests.

  • Changelog

How to contribute#

Development happens on GitHub: ihrke/pypillometry

  • Use the issue tracker to report bugs or propose enhancements. A small example that shows the problem (e.g., with one of the example datasets) helps a lot.

  • Use pull requests to contribute code or documentation.

If you are new to GitHub, see About pull requests.

For development, install the package in editable mode with the test dependencies:

git clone https://github.com/ihrke/pypillometry.git
cd pypillometry
pip install -e ".[test]"

Package architecture#

Most functionality is available as methods of the data classes (GenericEyeData, PupilData, GazeData, EyeData). This makes it easy to find functions and to chain them into pipelines (see Data objects).

The computations themselves are implemented as stateless functions on numpy arrays in pypillometry.signal (see Signal processing). To add a new processing step, first write a function that works on arrays, then add a thin method to the appropriate class that calls it with the right data and parameters. Decorate the method with keephistory() so that it is recorded in the object’s history, and support eyes=, variables= and inplace= like the existing methods.

Documenting code#

Docstrings follow the NumPy style. Every public class and function should have a docstring that explains what it does, its parameters and its return value, ideally with a short example. The API reference is generated from them.

Tests#

Tests are in the tests/ folder and run with pytest:

pytest tests/

Run pytest on tests/ only; the repository root contains scripts that are not tests. The tests run automatically for every push and pull request on GitHub. New functions should come with tests: at a minimum, call them with reasonable arguments; better, compare the result to the expected output.

Building the documentation#

The documentation (this website) is built with Sphinx and the PyData Sphinx theme. Its sources are in the docs/ folder:

index.rst

landing page

getting_started/

installation, quickstart (a notebook), command-line tools

user_guide/

concepts, one page per topic

notebooks/

tutorials (Jupyter notebooks)

experimental/

pages and notebooks for experimental features

api/

API reference; the pages in api/generated/ are created by autosummary during the build and are not under version control

conf.py, _static/, _templates/

configuration, CSS and autosummary templates

Install the requirements and build the HTML pages from the repository root:

pip install -r docs-requirements.txt
make html                      # output in _build/html
make livehtml                  # rebuild automatically while editing

make clean removes the build directory _build.

Notebooks#

Notebooks are stored with their outputs and are not executed during the build (nbsphinx_execute = "never"). This keeps the build fast and independent of data downloads. After changing a notebook, or when the package changes in a way that affects its output, run it again and commit the result:

cd docs/notebooks
jupyter nbconvert --to notebook --execute --inplace blinks.ipynb

Use pp.logging_set_level("WARNING") at the top of a notebook to keep log messages out of the rendered pages. Cells can be hidden from the website by setting their metadata to {"nbsphinx": "hidden"}.

The documentation is built and published to GitHub Pages automatically for every push to master.

Logging#

The package logs with loguru. During development, it can help to see the debug messages of a single module only:

import pypillometry as pp
pp.logging_disable()
pp.logger.enable("pypillometry.eyedata.generic")
pp.logging_set_level("DEBUG")

Releases#

Version numbers follow the scheme x.y.z: increment z for bug fixes, y for new features and x for changes that break backward compatibility.

Releases are created on GitHub releases. A GitHub action then writes the tag into the file VERSION (it must follow PEP 440) and uploads the release to PyPI.

Major versions#

Version 2 (2025) is a rewrite that breaks the API of version 1. Version 1 is kept on the v1 branch and its documentation at https://ihrke.github.io/pypillometry/v1/html/.
