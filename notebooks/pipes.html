Pipeline-based processing in pypillometry#

[1]:

import pypillometry as pp
from pypillometry import u

pypillometry processes data in pipelines: processing steps (e.g., blink detection, a filter, downsampling) are combined with the | operator and applied to an EyeData object:

[2]:

# load a small example dataset
d = pp.get_example_data("rlmw_002_short")
d = d | pp.pupil.blinks_detect() \
      | pp.pupil.blinks_merge_close(distance=100 * u.ms) \
      | pp.pupil.lowpass_filter(3) \
      | pp.downsample(50)

This command loads a data file (here we use an example dataset included with pypillometry), detects blinks in the signal and masks them, merges short, successive blinks, applies a 3 Hz low-pass filter, and downsamples the signal to 50 Hz. The final result of this processing pipeline is stored in object d.

The steps for pupil data are pp.pupil.<method>(...), those for gaze data pp.gaze.<method>(...), and the generic steps are available at the top level of the package (pp.downsample, pp.crop, pp.scale, …). They take the same arguments as the methods of the same name (d.pupil.blinks_detect(), d.downsample(), …), which run the same code.

Here, for better visibility, we put each operation on a separate line. For that to work, we need to tell Python that the statement has not yet ended, which we achieve by putting a backslash \ at the end of each (non-final) line (or by putting the whole expression in parentheses).

Pipelines are values#

A combination of steps is a Pipeline. It can be stored in a variable, printed, and applied to as many datasets as needed (e.g., to all participants of a study):

[6]:

preproc = pp.pupil.blinks_detect() \
        | pp.pupil.blinks_merge_close(distance=100 * u.ms) \
        | pp.pupil.lowpass_filter(3)
print(preproc)

pp.pupil.blinks_detect() | pp.pupil.blinks_merge_close(distance=100 ms) | pp.pupil.lowpass_filter(3)

[7]:

d = pp.get_example_data("rlmw_002_short")
d2 = d | preproc | pp.downsample(50)
print(f"d has {len(d)} samples and {len(d.get_blinks()['left_pupil'])} blinks")
print(f"d2 has {len(d2)} samples and {len(d2.get_blinks()['left_pupil'])} blinks")

d has 20465 samples and 0 blinks
d2 has 2047 samples and 13 blinks

d | pipeline does not change d: it copies d once and applies all steps to the copy, which is returned. (Python reads d | a | b as (d | a) | b, which copies at each |; for large datasets, apply the whole pipeline at once, as in d | preproc or d | (a | b).)

Parameters that differ between participants can be passed with a small function that returns the pipeline:

[8]:

def preproc_subj(vel_onset):
    return pp.pupil.blinks_detect(vel_onset=vel_onset) | pp.pupil.lowpass_filter(3)

d2 = d | preproc_subj(vel_onset=-10)

If a step fails, the error message says which step it was.

Calling the methods directly#

The same operations are available as methods of the data object: the pupil methods in d.pupil, the gaze methods in d.gaze and the generic ones directly on d. This is convenient for single steps:

[9]:

d = pp.get_example_data("rlmw_002_short")
d.pupil.blinks_detect()
d.downsample(50)

In-place vs. copying data#

d | step never changes d. The methods, however, work in-place by default. That means, after running an operation (e.g., d.downsample()), the dataset will have changed and the returned object is the same object as d.

For example, the next code downsamples the data to 50 Hz and returns dataset d2. However, since the operation was in-place, the original dataset d has also changed:

[10]:

d = pp.get_example_data("rlmw_002_short")
d2 = d.downsample(50)
print(f"d has {len(d)} samples")
print(f"d2 has {len(d2)} samples")
print(f"d and d2 are the same: {d is d2}")

d has 2047 samples
d2 has 2047 samples
d and d2 are the same: True

This can be tricky when re-running a cell of a notebook as the operations will be applied again to the already processed data (i.e., blink detection, downsampling, smoothing etc. will be run multiple times on the same data).

This can be prevented by adding inplace=False to any operation or by using d.copy() explicitly:

[11]:

# using inplace=False
d = pp.get_example_data("rlmw_002_short")
d2 = d.downsample(50, inplace=False)
print(f"d has {len(d)} samples")
print(f"d2 has {len(d2)} samples")
print(f"d and d2 are the same: {d is d2}")

d has 20465 samples
d2 has 2047 samples
d and d2 are the same: False

[12]:

# using copy()
d = pp.get_example_data("rlmw_002_short")
d2 = d.copy()
d2.downsample(50)
print(f"d has {len(d)} samples")
print(f"d2 has {len(d2)} samples")
print(f"d and d2 are the same: {d is d2}")

d has 20465 samples
d2 has 2047 samples
d and d2 are the same: False

If you prefer that operations never change the object they are called on, you can change the default for a single object (inplace=False when creating it) or for the whole package with pp.set_default_inplace():

[13]:

pp.set_default_inplace(False)
d = pp.get_example_data("rlmw_002_short")
d2 = d.downsample(50)
print(f"d has {len(d)} samples")
print(f"d2 has {len(d2)} samples")
pp.set_default_inplace(True)  # back to the default

d has 20465 samples
d2 has 2047 samples
