Processing monocular and binocular data#

[1]:

import pypillometry as pp
import numpy as np

Data in pypillometry can contain different variables from different eyes. The variables and eyes supported when importing raw data are

  • left_x, right_x (x-coordinate in screen coordinates from the eyetracker)

  • left_y, right_y (y-coordinate in screen coordinates from the eyetracker)

  • left_pupil, right_pupil (pupil size from left and right eye)

All of them are held in an EyeData object. Any of these variables can be left out, but at least one must be given, and the x and y of an eye go together:

  • pupil data only: at least one of left_pupil, right_pupil (or both)

  • gaze data only: at least one of (left_x, left_y) and/or (right_x, right_y)

  • both: x, y and pupil from at least one eye

For example, let’s simulate some basic data:

[2]:

rng = np.random.default_rng(42)
n = 1000
left_x, right_x = rng.normal(size=n), rng.normal(size=n)
left_y, right_y = rng.normal(size=n), rng.normal(size=n)
left_pupil, right_pupil = rng.normal(size=n), rng.normal(size=n)
time = np.arange(n)  # time in ms

# these are all ok
dpupil = pp.EyeData(left_pupil=left_pupil, right_pupil=right_pupil, time=time)
dgaze = pp.EyeData(left_x=left_x, left_y=left_y, right_x=right_x, right_y=right_y, time=time)
deye = pp.EyeData(left_x=left_x, left_y=left_y, left_pupil=left_pupil, time=time)

The x and y of an eye go together, so giving only one of them (here, left_x without left_y) fails:

Almost all of pypillometry’s functions have keyword arguments eyes= and variables= that specify which eyes/variables to operate on. By default, all variables and eyes are processed.

For example, we can run the scale() function that re-scales the data to have mean 0 and standard deviation 1. Here, we use the context manager pp.loglevel("DEBUG") to see what pypillometry does internally:

Which functions work on which data?#

Not all of pypillometry’s functions can be applied to all variables. The functions that are specific to pupil data are in the namespace d.pupil (e.g., d.pupil.blinks_detect()), those that only work on gaze (x/y) data in d.gaze (e.g., d.gaze.mask_offscreen()). The methods of EyeData itself operate on all variables (which may or may not make sense, it is up to you to check!).

Functions that work only on pupillometric data raise an error for data without pupil size:

dpupil.pupil.blinks_detect()  # works fine

Creating new variables or eyes#

In some cases, new variables or “eyes” can be created. For example, we might want to reduce a binocular dataset to one where we average the timeseries from the two eyes. In that case, we can use the function merge_eyes():

[11]:

dpupil.merge_eyes(eyes=["left", "right"], variables=["pupil"], method="mean")

We can see that a new “eye” called mean with variable pupil (i.e., mean_pupil) has been created. The original data left_pupil and right_pupil have been kept (this can be changed by using keep_eyes=False).

In other cases, the package creates new variables. For example, the function pupil.estimate_baseline() estimates the tonic fluctuations in the pupil (see Mittner & Groot, 2025) and creates a new variable <eye>_baseline. The baseline estimation does not work with missing data, so we first detect and interpolate blinks:

[12]:

d = pp.get_example_data("rlmw_002_short")
d = d | pp.pupil.blinks_detect() | pp.pupil.blinks_interpolate() | pp.pupil.estimate_baseline()
d.variables
