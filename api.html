API documentation¶

Python-package to help with processing of pupillometric and eyetracking data.

This package provides classes for handling pupillometric and eyetracking data as well as tools for plotting and analyzing these data.

Unit Handling:¶

Times, distances and angles can carry units, either from the pypillometry.u namespace (3 * u.min, (-200, 800) * u.ms, 60 * u.cm, 20 * u.deg) or as strings ("3 min", "60 cm", "20 deg").

Primary classes¶

Several different classes are available for handling different types of eye data.

  • PupilData: If you have only pupillometric data, use this class.

  • GazeData: If you only have gaze data, use this class.

  • EyeData: If you have both gaze and pupillometric data, use this class.

These classes inherit from GenericEyeData, which provides some basic, shared functionality for handling eye data.

The data inside each of these classes is stored in the data attribute, which is a dictionary-like object of type EyeDataDict.

Each of these classes provides access to a matching plotter object (from module pypillometry.plot) that is stored in the plot attribute.

correct_pupil_foreshortening(eyes=[], midpoint=None, store_as='pupil', inplace=None)[source]¶

Correct pupil data using a simple algorithm to correct for foreshortening effects.

Correct the pupil data for foreshortening effects caused by saccades/eye movements. This method is based on a simple algorithm that assumes the pupil appears perfectly circular when fixating midpoint: for each sample, the distance \(\Delta\) (in mm) of the gaze position from midpoint is computed and the pupil signal is multiplied by the correction factor \(\sqrt{1+\Delta^2/d^2}\), where \(d\) is the eye-to-screen distance from the experimental setup. For a more complete model that also estimates the camera position, see fit_foreshortening().

Relevant publication (not the description of the algorithm used here): https://link.springer.com/article/10.3758/s13428-015-0588-x

  • [ ] TODO: when using interpolated pupil data, x/y data may still be missing. Make sure that the pupil data is not touched where x/y is missing

Parameters:

  • eyes (list) – Which eyes to correct. If empty, correct all available eyes.

  • midpoint (tuple or None) – The center of the screen (x,y) in pixels where it is assumed that the pupil is completely circular. If None, the midpoint is taken to be the center of the screen as registered in the experimental_setup.

  • store_as (str) – name of the variable in which to store the corrected pupil data (as data[eye, store_as]); the default “pupil” replaces the original pupil data

  • inplace (bool or None) – Whether to modify the object in place or return a new object. true: modify in place false: return a new object None: use the object’s default setting (initialized in __init__)

Returns:

An EyeData object with the corrected pupil

Return type:

fit_foreshortening(eye, r=None, d=None, intervals=None, target_fs=50.0, lowpass_freq=4.0, lambda_smooth=1.0, knots_per_second=1.0, initial_theta=None, initial_phi=None, verbose=True)[source]¶

Fit foreshortening correction model to estimate camera geometry and true pupil size.

This method implements Stage 1 of the foreshortening correction algorithm, which jointly estimates the camera position (theta, phi) and the temporal dynamics of true pupil size A0(t) using B-splines. The data is automatically preprocessed (filtered and downsampled) before fitting.

Parameters:

  • eye (str) – Which eye to fit (‘left’ or ‘right’)

  • r (Union[float, str, None]) –

    Eye-to-camera distance. If not provided, uses the r from experimental_setup.

    • Plain number: assumed to be mm (with warning)

    • String: e.g., “600 mm”, “60 cm”

    • Quantity: e.g., 600 * u.mm

  • d (Union[float, str, None]) –

    Eye-to-screen distance. If not provided, uses the d from experimental_setup.

    • Plain number: assumed to be mm (with warning)

    • String: e.g., “700 mm”, “70 cm”

    • Quantity: e.g., 700 * u.mm

  • intervals (Optional[Intervals]) – Time intervals to use for fitting. If None, uses all available data. Useful for fitting only on calibration periods. Intervals in any time units or in sample indices (units=None) are accepted; a plain list of (start, end) tuples is taken as ms.

  • target_fs (float) – Target sampling rate in Hz after downsampling for efficiency. Pupil dynamics are typically well-preserved at 50 Hz.

  • lowpass_freq (float) – Lowpass filter cutoff frequency in Hz. Removes high-frequency noise before downsampling. Should be below target_fs/2 (Nyquist).

  • lambda_smooth (float) – Smoothness regularization weight. Higher values produce smoother A0(t) estimates. Tune via cross-validation if needed.

  • knots_per_second (float) – Number of B-spline knots per second. Controls temporal resolution of A0(t) model. Typical values: 0.5-2.0.

  • initial_theta (Union[float, str, None]) –

    Initial guess for camera polar angle. If None, uses pi/2 (horizontal) as starting point.

    • Plain number: assumed to be radians (with warning)

    • String: e.g., “20 degrees”, “0.349 radians”

    • Quantity: e.g., 20 * u.deg

  • initial_phi (Union[float, str, None]) –

    Initial guess for camera azimuthal angle. If None, uses 0 (camera on x-axis) as starting point.

    • Plain number: assumed to be radians (with warning)

    • String: e.g., “-90 degrees”, “-1.57 radians”

    • Quantity: e.g., -90 * u.deg

  • verbose (bool) – Print optimization progress and fit statistics.

Returns:

calibration – Fitted calibration object containing camera geometry (theta, phi), spline coefficients for A0(t), and fit quality metrics.

Return type:

ForeshorteningCalibration

Raises:

ValueError – If specified eye doesn’t exist or lacks gaze/pupil data, if the experimental setup is not set or lacks required information, if lowpass_freq is not below the Nyquist frequency or if fewer than 100 valid samples are available.

Notes

The model is:

A_measured(x,y,t) = A0(t) * cos(alpha(x,y; theta, phi))

where:

  • A0(t) = sum_k a_k * B_k(t) is modeled with B-splines

  • cos(alpha) is the foreshortening factor depending on viewing angle

  • theta, phi parameterize camera position in spherical coordinates

The optimization minimizes:

sum_i (A_i - A_pred_i)^2 + lambda_smooth * sum_k (a_{k+1} - a_k)^2

Examples

>>> import pypillometry as pp
>>> data = pp.EyeData.from_eyelink('recording.edf')
>>>
>>> # Set experimental setup
>>> data.set_experimental_setup(
...     screen_resolution=(1920, 1080),
...     physical_screen_size=("52 cm", "29 cm"),
...     eye_to_screen_center="65 cm",
...     camera_offset=("0 cm", "-30 cm", "0 cm"),
... )
>>>
>>> # Fit on calibration period (first 2 minutes)
>>> cal_intervals = pp.Intervals([(0, 120000)], units="ms")
>>> calib = data.fit_foreshortening(
...     eye='left',
...     intervals=cal_intervals
... )
>>>
>>> # Or provide r and d explicitly
>>> calib = data.fit_foreshortening(
...     eye='left',
...     r="60 cm",
...     d="70 cm",
...     intervals=cal_intervals
... )
>>>
>>> # Inspect fit quality
>>> print(calib)
>>> print(f"R² = {calib.fit_metrics['r2']:.3f}")
>>>
>>> # Compute correction for all data
>>> correction_factor = calib.get_correction_factor(
...     data['left', 'x'],
...     data['left', 'y']
... )
>>> corrected_pupil = data['left', 'pupil'] * correction_factor

pupil_blinks_detect(eyes=[], min_duration=20, blink_val=0, winsize=11, vel_onset=-5.0, vel_offset=5.0, vel_onset_min_duration=5.0, vel_offset_min_duration=5.0, strategies=['zero', 'velocity'], apply_mask=False, ignore_existing_mask=False, inplace=None)[source]¶

Detect blinks in the pupillary signal using several strategies. First, blinks are detected as consecutive sequence of blink_val (f.eks., 0 or NaN). Second, blinks are defined as everything between two crossings of the velocity profile (from negative to positive).

Detected blinks are always stored in the object (retrieve them with get_blinks()). When apply_mask=True, the blinks are also applied as masks to the data. When apply_mask=False (default), the detected blinks are returned as Intervals objects.

Finally, detected blinks have to be at least min_duration ms.

Parameters:

  • eyes (list) – list of eyes to process; if empty, all available eyes are processed

  • min_duration (float) – minimum duration (in ms, or with units) for a sequence of missing numbers to be treated as blink

  • blink_val (float) – “missing value” code for the “zero” strategy. Missing samples (NaN) are always detected; samples equal to blink_val (default 0) are detected in addition. Use np.nan to detect only NaN (e.g., for baseline-corrected data where 0 is a valid value). The “zero” strategy always uses the raw data, so regions masked for other reasons are not detected as blinks.

  • winsize (float) – window-size for Savitzky-Golay velocity estimation (in ms, or with units)

  • vel_onset (float or str) –

    velocity threshold to detect blink onset (negative value).

    • If float: threshold in pupil-units per millisecond (e.g., -5.0)

    • If str: percentile of velocity distribution (e.g., “5%” for bottom 5%)

  • vel_offset (float or str) –

    velocity threshold to detect blink offset (positive value).

    • If float: threshold in pupil-units per millisecond (e.g., 5.0)

    • If str: percentile of velocity distribution (e.g., “95%” for top 5%)

  • vel_onset_min_duration (float) – minimum duration (in ms, or with units) that velocity must exceed threshold to detect as onset (to avoid noise-induced false detections)

  • vel_offset_min_duration (float) – minimum duration (in ms, or with units) that velocity must exceed threshold to detect as offset (to avoid noise-induced false detections)

  • strategies (list) – list of strategies to use; so far, use a list containing any combination of “zero” and “velocity”

  • apply_mask (bool) – if True, apply detected blinks as masks to the data and return the object if False (default), return detected blinks as Intervals (or dict of Intervals)

  • ignore_existing_mask (bool) – if True, use raw data ignoring existing masks if False (default), only detect blinks in non-masked data (already masked regions are skipped)

  • inplace (bool or None) – if True, make change in-place and return the object if False, make and return copy before making changes if None, use the object-level setting

Returns:

If apply_mask=True: returns the object (for chaining) If apply_mask=False and single eye: returns Intervals object If apply_mask=False and multiple eyes: returns dict of Intervals objects (keys like "left_pupil")

Return type:

PupilData or Intervals or dict

pupil_blinks_interpolate(eyes=[], store_as='pupil', method='mahot', winsize=25, vel_onset=-5.0, vel_offset=5.0, margin=(10, 30), blinkwindow=500, interp_type='cubic', inplace=None)[source]¶

Interpolating blinks in the pupillary signal.

Implements the blink-interpolation method by Mahot (2013).

Mahot, 2013: https://figshare.com/articles/A_simple_way_to_reconstruct_pupil_size_during_eye_blinks/688001.

The blinks to interpolate are taken from the blinks stored in the object, so blinks have to be detected first (e.g., using pupil_blinks_detect()). The on- and offsets of each blink are refined using the velocity profile before interpolating. Blinks that are so close that the anchor points of one fall into the other are merged and interpolated together. Interpolated samples remain masked; the interpolated blinks can be retrieved with get_interpolated_blinks().

This procedure relies heavily on eye-balling (reconstructing visually convincing signal), so it can help to inspect the result visually (e.g., using plot_blinks()) to set good parameter values for winsize, vel_onset, vel_offset and margin (see paper linked above).

Parameters:

  • eyes (str | list) – str or list of eyes to process; if empty, all available eyes are processed

  • store_as (str) – how to store the interpolated data; either “pupil” (default) which replaces the original pupil data or a string that will be used as the new variable name in the data (e.g., “pupilinterp”)

  • method (str) – method to use; so far, only “mahot” is implemented

  • winsize (float) – size of the Savitzky-Golay window (in ms, or with units)

  • vel_onset (float or str) –

    velocity threshold to detect blink onset (negative value).

    • If float: threshold in pupil-units per millisecond (e.g., -5.0)

    • If str: percentile of velocity distribution (e.g., “5%” for bottom 5%)

  • vel_offset (float or str) –

    velocity threshold to detect blink offset (positive value).

    • If float: threshold in pupil-units per millisecond (e.g., 5.0)

    • If str: percentile of velocity distribution (e.g., “95%” for top 5%)

  • margin (Tuple[float, float]) – margin that is subtracted/added to onset and offset (in ms, or with units, e.g. (10, 30) * u.ms)

  • blinkwindow (float) – how much time before and after each blink to include (in ms, or with units)

  • interp_type (str) – type of interpolation accepted by scipy.interpolate.interp1d()

  • inplace (bool or None) – if True, make change in-place and return the object if False, make and return copy before making changes if None, use the object-level setting

pupil_merge_eyes(method='local_offset', lowpass_cutoff=0.2, max_iter=10, keep_eyes=True, inplace=None)[source]¶

Merge pupil data from both eyes into a single “merged” variable.

This method combines left and right pupil signals, handling missing data (masked values) intelligently. Where both eyes are valid, the signals are averaged to reduce noise. Where only one eye is valid, that eye’s data is used (with offset correction if applicable).

Parameters:

  • method (str) –

    Method for merging the two eyes. Options:

    • ”local_offset” (default): Compute a slowly-varying offset between eyes using lowpass filtering. This handles drift over the session. The right eye is shifted to match the left eye’s level before merging.

    • ”offset”: Use a single global offset (mean difference) computed over the entire signal where both eyes are valid.

    • ”both_available”: Only use data where both eyes are valid (take mean). Timepoints where only one eye is valid remain masked.

    # TODO: Implement “signal_quality” method that weights eyes by their # local signal quality (SNR), giving more weight to the cleaner eye.

  • lowpass_cutoff (float) – Cutoff frequency (Hz) for the lowpass filter used in “local_offset” method. Lower values produce a more stable offset that only tracks very slow drift. Default is 0.2 Hz (~5 second time constant).

  • max_iter (int) – Maximum iterations for iterative lowpass filtering in “local_offset” method. Default is 10.

  • keep_eyes (bool) – If True (default), keep the original left/right pupil data. If False, remove the original eye data after merging.

  • inplace (bool | None) – If True, modify in-place. If False, return a copy. If None, use the object’s default setting.

Returns:

The object with merged pupil data stored as “merged_pupil”.

Return type:

PupilData

Raises:

ValueError – If only one eye is available (nothing to merge). If an unknown method is specified.

Notes

The merged signal is stored as “merged_pupil” and can be accessed via data[“merged”, “pupil”] or data[“merged_pupil”].

The mask for the merged signal reflects which timepoints have valid data: - For “local_offset” and “offset”: masked only where BOTH eyes are masked - For “both_available”: masked where EITHER eye is masked Masked samples still hold the merged stored values (e.g., interpolated blinks), computed as for valid samples (NaN only if both eyes are NaN).

The “local_offset” method is recommended for most use cases as it: 1. Uses all available data (doesn’t discard single-eye timepoints) 2. Handles session-long drift in the inter-ocular difference 3. Produces smooth transitions at boundaries between single/both-eye regions

Examples

>>> # Default: local offset correction
>>> data.pupil_merge_eyes()
>>> merged = data["merged", "pupil"]

>>> # Use global offset (simpler, assumes no drift)
>>> data.pupil_merge_eyes(method="offset")

Container for intervals with metadata.

This class wraps a list of (start, end) intervals and provides additional metadata such as units, labels, and associated event information.

Usually, Intervals objects are not created directly but returned by methods of the eye-data classes, e.g., get_intervals() (event-locked intervals, input for get_segments()), get_blinks() or mask_as_intervals(). Detection methods such as pupil_blinks_detect() store their results as Intervals. Several Intervals can be combined with + or merge_intervals() and subtracted with -.

Parameters:

  • intervals (list of tuples, np.ndarray or Quantity) – Intervals as list of (start, end) tuples or 2D array; can carry units, e.g. [(0, 100), (200, 300)] * u.ms or [("1 min", "2 min")]

  • units (str, Unit or None) – Units of the intervals (“ms”, “sec”, “min”, “h”, or None for indices). Can be omitted if intervals carry units; otherwise, intervals with units are converted to units.

  • label (str, optional) – Descriptive label for the interval collection

  • event_labels (list, optional) – Event labels corresponding to each interval

  • event_indices (np.ndarray, optional) – Indices (into the dataset’s events) of the event corresponding to each interval

class pypillometry.EyeDataDict(*args, **kwargs)[source]¶

A dictionary that contains 1-dimensional ndarrays of equal length and with the same datatype (float). Drops empty entries (None or length-0 ndarrays).

Keys stored in this dictionary have the following shape: (eye)_(variable) where eye can be any string identifier (e.g., “left”, “right”, “mean”, “median”, “regress”, or any other custom identifier) and variable is any string identifier (e.g., “x”, “y”, “pupil”, “baseline”, “response”, or any other custom identifier).

Values are stored as given (converted to float); NaN values are masked. No other values are treated as missing (e.g., a pupil size of 0 is kept); converting missing-value codes to NaN is up to the code that reads the data.

The dictionary can be indexed by a string “eye_variable” or by a tuple (“eye”, “variable”) like data[“left”,”x”] or data[“left_x”].

Uses asymmetric Savitzky-Golay velocity estimation: - Backward-looking velocity for onset detection (so future zeros/NaN don’t affect the estimate) - Forward-looking velocity for offset detection (so past zeros/NaN don’t affect the estimate)

Estimates signal quality by separating the signal into a slow “true signal” component (via lowpass filtering) and a fast “noise” component (the residual). Quality is then computed in sliding windows.

  • signal (np.ndarray or np.ma.MaskedArray) –

io.py¶

Read/Write data from/to disk.

Reading EDF files is slow: read_eyelink() (and from_eyelink()) takes about a minute for a 90 MB EDF file (64 min of binocular data at 1000 Hz), mostly in the eyelinkio package. It is therefore recommended to convert EDF files once and to work with the converted files, e.g., with the command-line program edf2pypil (edf2pypil recording.edf writes recording.pkl) or with write_pickle(). Reading the pickle file with read_pickle() took 0.1-0.25 s for the same recordings (more than 200 times faster; from a slow disk it can take a few seconds). Pickle files are larger (about 400 MB for a 90 MB EDF file) and should only be read from trusted sources.

pypillometry.io.fetch_url(url, cache_file=None, cache_dir=None, force_download=False, session=None)[source]¶

Download an HTTP(S) or SSH URL to a local file, with caching.

HTTP(S) URLs are downloaded with download() (OSF client URLs such as https://osf.io/<id> are converted to download URLs).

SSH URLs have the form ssh://[user@]host[:port]/path and are downloaded with the system’s scp, which uses ~/.ssh/config (host aliases, users, keys). Only key-based login is supported: password prompts are disabled (BatchMode=yes). The path is absolute on the server; use ssh://host/~/path for a path relative to the home directory. An SSH URL ending in / downloads the whole folder.

Parameters:

  • url (str) – HTTP(S) or SSH URL

  • cache_file (Optional[str]) – local filename to store the download in

  • cache_dir (Optional[str]) – directory to store the download in (used if cache_file is None); the file is saved as cache_dir/<host>/<path>. If both are None, a new temporary directory is used. The location is logged.

  • force_download (bool) – if False (default), an existing local copy is reused; if True, the file is downloaded again

  • session (Optional[Session]) – requests session for HTTP(S) downloads (e.g., from osf_authenticate() for private OSF projects)

Returns:

local path of the downloaded file (or folder)

Return type:

str

pypillometry.study.load_study_local(path, config_file='pypillometry_conf.py', subjects=None, cache_dir=None, autodelete=None, force_download=False)[source]¶

Read a study from a local directory (or an SSH URL) using the configuration file.

The configuration file must define a dict raw_data (subject ID -> dict of data files, relative to path) and a function read_subject(info) that returns the data for one subject; it is called with the working directory changed to path.

If path is an SSH URL (ssh://server/folder/, see fetch_url()), the configuration file and the data files of the selected subjects are downloaded to cache_dir before they are read.

Parameters:

  • path (str) – Local path or SSH URL where the study data is stored

  • config_file (str) – Name of the configuration file. Default is “pypillometry_conf.py”. It is first looked up in the current working directory and, if not found there, in path.

  • subjects (list[str]) – List of subject IDs to load. If None, all subjects will be loaded. If a subject ID is provided that doesn’t exist in the data, it will be skipped.

  • cache_dir (Optional[str]) – only for SSH URLs: directory to download the files to; if None, a temporary directory is used

  • autodelete (Optional[bool]) – only for SSH URLs: if True, the data files of each subject are deleted after they were read (and a temporary directory is removed at the end). If None (default), this is done only when a temporary directory is used (no cache_dir).

  • force_download (bool) – only for SSH URLs: download files again even if they are already in cache_dir

Returns:

  • study_data (dict) – Dictionary containing the loaded study data (subject ID -> result of read_subject)

  • config (module) – Module containing the configuration (pypillometry_conf.py imported as a module)
