Loading and saving data#

Eyelink EDF files#

EDF files from SR Research Eyelink eye trackers are read with from_eyelink(), which uses the eyelinkio package:

import pypillometry as pp

d = pp.EyeData.from_eyelink("recording.edf")
p = pp.PupilData.from_eyelink("recording.edf")   # pupil only
g = pp.GazeData.from_eyelink("recording.edf")    # gaze only

The result contains all samples, all messages (as events), the screen resolution and the calibration/validation results (as SpatialCalibration objects in d.calibration). Eyelink codes missing pupil samples as 0; these are converted to NaN and masked. Eyelink’s own messages (calibration, drift correction, …) are removed from the events unless you pass remove_eyelink_triggers=False.

Instead of a local file name, you can also pass an HTTP(S) URL or an SSH URL (ssh://server/folder/file.edf). The file is then downloaded and cached (see fetch_url()).

Reading large EDF files is slow. Save the result (see below) or convert the file once with the command-line tool edf2pypil.

See Importing data from Eyelink EDF files.

Text files and your own arrays#

Data from other eye trackers, or exported as text (e.g., Eyelink’s ASC format), can be read with numpy or pandas and passed to the constructors as arrays:

d = pp.EyeData(
    time=df["time"],                      # in ms
    left_x=df["lx"], left_y=df["ly"], left_pupil=df["lp"],
    right_x=df["rx"], right_y=df["ry"], right_pupil=df["rp"],
    event_onsets=events["time"],          # in ms
    event_labels=events["label"],
    sampling_rate=500,
    name="subject01",
)

Any of the eyes or variables can be left out. PupilData and GazeData take the corresponding subset of arguments. Gaps in the time vector (e.g., when recording was paused) are filled with masked samples, so the samples are evenly spaced.

See Importing data from Eyelink ASC files for a complete example.

Example datasets#

A few datasets are available for trying out the package:

pp.get_available_datasets()                # names and descriptions
d = pp.get_example_data("rlmw_002_short")  # 40 s, included in the package
d = pp.get_example_data("rlmw_002")        # 20 min, downloaded from OSF

See Example datasets included in pypillometry.

Saving and loading objects#

Processed objects, including their history, are saved with write_file() and loaded with from_file():

d.write_file("subject01.pypil")
d = pp.EyeData.from_file("subject01.pypil")

Files are pickle files compressed with zstd (pass compress=False to turn this off). write_pickle() and read_pickle() do the same for any Python object, e.g., a list of objects or a SegmentedEyeData. read_pickle() also reads files from a URL.

Warning

Pickle files can contain arbitrary code. Only load files from sources you trust.

If the filename ends in .h5 or .hdf5, the object is saved in an HDF5 file instead:

d.write_file("subject01.h5")
d = pp.EyeData.from_file("subject01.h5")

HDF5 files do not run code when they are read, and other programs (e.g., h5py, R or MATLAB) can read them: the data are datasets (tx, data/values/left_pupil, data/mask/left_pupil, …), the other information (name, sampling rate, blinks, history, …) is stored in groups and attributes. They work for eyedata objects and SegmentedEyeData (not for arbitrary Python objects). Values in info or params that HDF5 cannot store are saved as text (with a warning). The loading functions detect the format from the file content.

Both formats store a versioned description of the object. Files written by older versions of pypillometry are upgraded when they are loaded.

Saved files can be inspected with pypilinfo and opened in the viewer with pypilview (see Command-line tools).

Whole studies#

For studies with many participants, a small configuration file describes where the raw data are and how to read them. load_study_local() and load_study_osf() then load all participants at once (see Studies with many participants).
